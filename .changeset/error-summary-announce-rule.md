New `getErrorSummary(fieldErrors, options?)` (and its `GetErrorSummaryOptions` type): the one-line validation summary for `ObjectPageFooter`'s `message`, or `undefined` when there is no error. It counts the invalid paths of `fieldErrors` (keys whose value is not `undefined`, also paths with no control on the page and fields that are `forced`/`locked`/`disabled`) plus, when passed, `options.formErrors`. Default text in Italian ("1 campo non valido" / "N campi non validi"); `options.message: (count) => string` replaces it (the library does not translate: pass your own text). A pure function: the footer keeps its API and does not read the form.

The error announcement rule is now written in the JSDoc of `useObjectPageForm` and `ObjectPageFooter`: field errors are not live (`aria-invalid` + `aria-describedby`, read when `useFocusFirstInvalidField` moves the focus there); the validation summary and the `saveError` go to the footer's polite `role="status"`, and the `saveError`, when present, takes the place of the summary; a root error (`formErrors`, an issue with no path such as a `refine` on the whole object) has no `Field`, so the consumer renders its messages, e.g. a `MessageStrip` `tone="error"` (`role="alert"`) at the top of the form, while the footer summary counts it (pass a `message` such as "N errors" if you use root rules: the default text says "campi"); a blocking page error is a `MessageStrip` (`role="alert"`). The documented recipe combines the save error and the summary with `||`, not `??`, so a save error with an empty text does not hide the summary. The doc of the footer's `message` prop now says that the summary with the count belongs there and the single field messages do not. No ARIA role changes.
