# Formrail Pro (preview)

`@formrail/pro` extends the free `@formrail/core` with components for heavier
enterprise screens. This site shows the Pro components that exist today, running against the same
design tokens and primitives as the free library. Nothing here is a mock-up: each story renders the
actual component.

## Components available today

### Change Summary

A review of what is about to be saved: every changed field with its label and a readable before/after
value, computed against the value saved on the server rather than the value the page opened with.

- [Change Summary](?path=/docs/pro-changesummary--docs): the component, its states and value types.
- [Invoices with Change Summary](?path=/docs/pro-showcase-invoices-with-change-summary--docs): the
  invoice CRUD showcase with a "Review changes" step before saving, and "Simulate server update": the
  invoice changes on the server while you edit it, your changes are kept and the conflicts are resolved
  field by field.
- [Record editing integrity](?path=/docs/pro-showcase-record-editing-integrity--docs): the same "Review
  changes" and "Simulate server update" on the sales orders: lines compared by id and named by their
  product, a mere reorder of the lines told apart, amounts in the order's currency, and an order deleted on
  the server while you edit it.

### Virtual List Report

The List Report with virtualized rows, for datasets far beyond what a plain table can render. It keeps
the same props and `useListReport` state as the free List Report, and behaves as the free table below
a configurable row threshold.

- [Virtual List Report](?path=/docs/pro-floorplans-virtual-list-report--docs): up to 200,000 rows,
  range selection and scroll restoration.

### Form rebase

A three-way merge of a new server version into the user's draft: paths the user did not touch take the
server value, paths changed by both sides keep the user's value and are listed as conflicts.

- [Form rebase](?path=/docs/pro-patterns-form-rebase--docs): `useFormRebase`, `computeRebase` and the
  conflict resolution.
- [Rebase notice](?path=/docs/pro-rebasenotice--docs): "This record was updated while you were
  editing", with the server changes applied and each conflict with both values and the two choices.

### React Hook Form

The Change Summary and the form rebase on a React Hook Form form, without the free library:
`useReactHookFormBinding(form)` from `@formrail/pro/react-hook-form` gives the engines snapshots of the
values and of the saved baseline, and applies a server update without marking the form dirty.

- [React Hook Form](?path=/docs/pro-integrations-react-hook-form--docs): `useReactHookFormBinding` with
  `useChangeSummary` and `useFormRebase`, asynchronous loading, a save with a server update queued.

### TanStack Form

The same engines on a TanStack Form form, without the free library: `useTanStackFormBinding(form)` from
`@formrail/pro/tanstack-form` gives them snapshots of the values and of the saved baseline, and applies a
server update without touching the meta of the fields or running their listeners.

- [TanStack Form](?path=/docs/pro-integrations-tanstack-form--docs): `useTanStackFormBinding` with
  `useChangeSummary` and `useFormRebase`, asynchronous loading, a save with a server update queued.
